# 漢字詳細の行内展開（P1）

2026年10月12日、KanjiVariants 1.2.0 / .NET SDK 10.0.401。

## 実装範囲

既存の診断結果3列、適合判定、候補・並び・コピー・位置・コードポイントを維持し、元の文字をbuttonに変更しました。詳細は直下のcolspan=3の行に表示し、複数行を同時に開いたままにできます。同じ行を押すとその行だけ閉じ、他の行は維持します。閉じた詳細の要素は空のhidden行とし、aria-controlsの参照先を常に保持します。

基本情報、VSの有無・コードポイント、5集合への所属、常用漢字本表字・掲載音訓・用例・備考、教育漢字・配当学年、人名用863字と常用を含む分類を表示します。音訓・用例・備考は原典の文字列を維持します。音読みと訓読みはKanjiReading.Typeで分類し、空一覧を表示せず、同一の字単位の備考は一度だけ表示します。

詳細取得はCharacterDetailsService.Getが個別の公開APIを組み合わせて実施します。使用APIはKanjiCharacter.TryParse、Kanji.IsSupported、JoyoKanji.Get、EducationKanji.GetGrade、JinmeiyoKanji.IsJinmeiyoKanji、IsNameUsableKanjiです。返却Entryは共有し、不要な一覧複製をしません。例外は元表現を保持したエラーモデルとして返します。

Analyze、MjCharacter.Find、GetByMjGlyphName、JoyoKanjiEducation.GetReadingsは呼びません。既存のMJ縮退候補は既存処理のままです。MJ詳細初期化の内部状態を測定する公開APIはないため、呼び出し経路とソースの確認に基づいています。

## 状態・対象外入力

CharacterDetailsSessionは診断結果ごとに作り、初期キャッシュ0件。開いたときだけ取得し、OriginalをStringComparer.Ordinalで比較します。文字情報のキーに位置を含めず、展開中の行はUtf16Index別の辞書で管理します。同じ文字が複数行で開いていてもModelを共有し、取得時のキャッシュ利用・計測情報は行ごとに保持します。再診断で結果の参照が変わるとSessionを破棄します。既存のDiagnosticResultsのkeyも維持します。

TryParse失敗は「詳細APIの取得対象外」と表示し、漢字ではないと断定しません。所属のfalseを捏造せず、基本情報だけを表示します。不正UTF-16は既存Item.Reasonに従い「Unicodeスカラーなし」と表示し、U+FFFDへ読み替えません。登録済み・未登録VSとも元の表現を保持します。VS範囲の確認は表示専用のRune列挙で、登録判定・単位分割・変換には使いません。

aria-expanded、aria-controls、ネイティブbuttonのEnter/Space、既存focus-visibleを使用し、開閉時にフォーカスを移動しません。候補コピーは独立しています。600px以下では詳細のdlを縦積みにし、通常診断セルのdata-label疑似要素との干渉を避けます。

## 複数行の詳細を開いたままにする改善

利用者の追加依頼に合わせ、同時1件の制限を解除しました。展開は行位置別に保持し、同じ行を押したときだけ閉じます。各行のModelは文字表現別のキャッシュを共有し、開いた行の取得時間・キャッシュ利用情報は個別に保持します。

Releaseビルドは警告0・エラー0、全1,752件の検証に成功。Release publish・Pagesサブパス／静的参照検証も成功しました。実ブラウザで高・丑・高の3行が同時に開き、キャッシュは2文字分、中央行をSpaceで閉じても両端の高が開いたままであること、再診断で全閉・キャッシュ0に戻ることを確認しました。警告・エラーログなし。画面証跡はartifacts/character-details-multiple.pngです。
